# Electron desktop build

## Development

```bash
npm run electron:dev
```

This starts Angular with the `local` configuration and opens it in Electron.

## Production package

```bash
npm run electron:build
```

The Windows installer is generated in `release/`.
For the release build used by auto updates, run:

```bash
npm run electron:release:win
```

This creates the NSIS installer, `latest.yml`, the blockmap, and a stable
`Almak-Setup-latest.exe` copy for the web download button.

For a faster package check without creating the installer:

```bash
npm run electron:pack
```

## Backend URL

The desktop build uses `src/environments/environment.electron.ts`.
Change `apiBaseUrl` there before building if the desktop app should call another backend instead of `https://almakk.ru/api`.

## Auto updates

Auto updates are wired through `electron-updater` and `electron-builder`.
The update URL in `package.json` points to:

```json
"publish": [
  {
    "provider": "generic",
    "url": "https://almakk.ru/downloads/"
  }
]
```

The update server must contain the artifacts generated by:

```bash
npm run electron:release:win
```

Upload the full contents needed by the updater to `/var/www/app/downloads/`:

```bash
release/latest.yml
release/Almak-Setup-<version>.exe
release/Almak-Setup-<version>.exe.blockmap
release/Almak-Setup-latest.exe
```

The app reads updates from:

```text
https://almakk.ru/downloads/latest.yml
```

The download button in the web app points to:

```text
https://almakk.ru/downloads/Almak-Setup-latest.exe
```

The `Deploy Desktop App` GitHub Actions workflow builds and uploads these
desktop artifacts through `workflow_dispatch` or a push of a `v*` tag.

Regular frontend deploys do not rebuild or upload the desktop installer.

Every release must have a higher `version` in `package.json`.

For production Windows releases, use a code signing certificate and remove the unsigned dev-only setting:

```json
"signAndEditExecutable": false
```


## Manual update check

The installed app checks for updates on startup. The sidebar also offers «Проверить обновление» until an update is ready to install. Manual checks display checking, download progress, latest-version or retryable error status. Checks cannot be duplicated during checking/downloading. Once downloaded, the action becomes «Установить обновление»; installation is also enabled on app quit.

The main process retains update state, so reloading the renderer or opening the menu after a download restores the install action. IPC only accepts requests from the main window. Development builds show that updates require the installed app and never contact the update server. The web app does not show these controls.

Run `npm run test:desktop` for updater state/retry tests; navigation component tests cover the desktop bridge, progress, ready state and web visibility. The desktop tests also run in PR CI. To verify a real download/install, use two packaged versions and the configured update server; development builds do not exercise installation.
