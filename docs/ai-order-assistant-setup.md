# ИИ-помощник: подключение и проверка

Реализация находится в ветках `dev` фронтенда и бэкенда. В D1 черновики и переписки сохраняются на сервере; зарегистрированный заказ появляется только после подтверждения в обычной форме. D1 пока проверен локально, ещё не опубликован. [Контракт и порядок выпуска](server-drafts.md).

## Подключение

В `.env` бэкенда добавить:

```env
AI_ORDER_DRAFTS_ENABLED=true
DEEPSEEK_API_KEY=your_private_key
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

Заменить placeholder ключом непосредственно в локальном или серверном `.env`, не в клиентском коде и не в коммите. Затем перезапустить бэкенд. При выключенном флаге или отсутствии ключа разбор возвращает 503; текст и черновик можно сохранить и заполнить вручную.

Реализация использует Chat Completions с JSON Output и отдельной серверной проверкой структуры. Инструкция — `almak-back/internal/aiorders/prompt.txt`. Схема разрешённых полей — `schema.json` в той же папке и её копия в `almak-front/src/app/ai-orders/`. При изменении поддерживаемых полей обе копии нужно обновить согласованно.

Источники контракта провайдера: [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), [JSON Output](https://api-docs.deepseek.com/guides/json_mode/). Имя модели настраивается через окружение.

## Как проверить вручную

1. Запустить бэкенд с `PORT=8081`, фронтенд — `npm run start:local`.
2. Войти и нажать иконку сообщения справа снизу.
3. Ввести тестовый заказ без реальных персональных данных:

   > Тестовый клиент, телефон 79000000000. Три одностворчатые межкомнатные двери Верона, белая эмаль, без стекла, поставщик Брона. Две 80 на 200, одна 70 на 200. По 12000 рублей. Доставка не нужна. Внесено 10000 рублей.

4. Отправить, проверить две позиции с количествами 2 и 1 и суммой товаров 36000 рублей. Дату можно явно выбрать в поле «Дата» обычной формы заказа.
5. Написать «Дверь шириной 70 сделай 60». Проверить изменение той же позиции без создания второго черновика.
6. Проверить ручную правку, сворачивание, переход в «Черновики», восстановление истории и изменение размера за верхний левый угол.
7. Нажать «Открыть черновик». Это сразу открывает редактор заказа; уточнения через чат остаются доступны до создания заказа. Убедиться, что редактор открывается сразу, а неизвестные поля остаются пустыми. Пропуски не мешают сохранить черновик.
8. Заполнить необходимые данные и нажать «Сохранить» только для регистрации окончательного заказа. Проверить параметры и расчёт. На рабочей БД не создавать тестовый заказ; окончательное сохранение проверять на отдельной локальной БД.
9. Проверить ошибку провайдера/выключенный флаг: текст не должен исчезать, черновик остаётся в списке.

Размеры без единиц считаются сантиметрами. Явные мм переводятся в единицы поля. Текущий API дверей использует целочисленные размеры в сантиметрах: дробный размер нельзя молча округлять; нужно уточнить, как оформить такой товар. У плинтуса высота в мм, длина в м.

## Хранение и ограничения

- Ключ черновиков: `ai_order_drafts_v1`; размер окна: `ai_chat_size`. Старые обычные черновики используют прежние ключи.
- Черновики общие для аккаунтов одного браузерного/Electron-профиля и не синхронизируются между устройствами.
- Исходный текст отправляется внешнему провайдеру только по кнопке отправки. В обычные серверные логи не пишутся текст, контактные данные, токены или ключ.
- Ручные правки защищены от ИИ: чтобы изменить вручную исправленное поле, снова отредактировать его в форме заказа или диалоге товара.
- Одна переписка — один черновик; «Новый чат» сохраняет предыдущую запись.
- До 100 позиций, до 1000 штук в одной позиции, до 20 уточнений; 10000 символов на сообщение, 256 КиБ на запрос, 45 секунд на ответ.
- Конфликт ревизий возвращает 409. Несохранённый ввод остаётся в открытом окне; можно сохранить отдельную копию, скачать свой вариант или загрузить серверный. Фоновое обновление не заменяет чужими правками открытый редактор.
- JSON Output обеспечивает JSON-формат, но не гарантирует правильность извлечённых сведений. Критичные поля проверяет менеджер; качество живой модели требует практической проверки на ваших заметках.

## Автоматические проверки

Frontend: `npm run check`, `npm run build`, `npm test -- --watch=false --browsers=ChromeHeadless`, `npm run build:electron`.

Backend: `go test ./...`, `go vet ./...`, `go build -o <temporary-output> ./cmd`.

Тесты проверяют неполные данные, расчёты/адаптер всех восьми типов, сохранение до обращения к API, устаревшие ответы, ошибки хранилища, отмену запроса при выходе, валидацию ответа провайдера и защиту ручных полей. Для HTTP-тестов используется локальный подставной провайдер; эти тесты не проверяют качество ответов живого DeepSeek.

## Результат локальной проверки реализации

2 ноября 2026 года: ESLint, отдельные TypeScript-проверки app/spec, 12 frontend-тестов ChromeHeadless, web- и Electron-сборки прошли. На бэкенде прошли `go test ./...`, `go vet ./...` и сборка. В web-сборке остаются предупреждения о размерах initial bundle и некоторых стилей; лимит ошибки не превышен.

В браузере на отдельном тестовом API проверены создание и уточнение одного черновика, переходы между страницами, resize, перенос в форму и экран шириной 390 px. Рабочая БД и живой DeepSeek в браузерных проверках не использовались. После подключения ключа отдельно проверен реальный DeepSeek через тот же Go-handler, без подключения к БД: извлечение двух позиций с разными размерами и суммой 36000 ₽, уточнение ширины одной позиции без изменения остальных данных, неполное описание без выдуманных цен/размеров и преобразование 800×2000 мм в 80×200 см. На неполном описании уточнён системный prompt, затем повторно проверены основной сценарий и уточнение. Успешные запросы заняли примерно 1,3–2,4 секунды; это отдельные пробы, а не гарантированное время ответа. `.env` исключён из Git, ключ в вывод и документацию не записывался.

## Обновление текстового чата

В чате нет редакторов полей и селектов: только сообщения, вопросы помощника и ссылки на черновик/заказ. Для нового черновика достаточно одного известного поля. «История чатов» переключает переписки, сохраняя их сообщения и набранный текст. После регистрации заказа переписка остаётся в истории с `orderId`, а в списке незавершённых черновиков её больше нет. Старые локальные записи совместимы; ранее удалённые переписки восстановить нельзя.

### Исправление открытия неполных черновиков

Промежуточный экран «Проверка черновика заказа», подтверждающая галочка и кнопка переноса удалены. Ссылка из чата сразу открывает редактор с данными клиента и частичными позициями. Черновик сохраняется при любом количестве заполненных полей. Неполные позиции остаются в частичной модели, без подстановки нулей в неизвестные цены и размеры. Проверка полноты и преобразование в окончательный API payload выполняются только при создании заказа.

## Товары из текста в обычном редакторе

Отдельная AI-карточка внутри заказа удалена. Все восемь типов распознанных товаров показываются в `OrderItemsListComponent` в обычных группах, с действиями редактирования, копирования и удаления. Меню «Добавить» создаёт товар после сохранения диалога; отмена не добавляет пустую позицию. Диалог неполного товара использует Material-контролы, сохраняет пропуски и не применяет типовые цены, размеры, покрытия или количества. Поставщики и покрытия доступны из справочников.

Частичные товары остаются в `AiDraft.order.items` как единственном источнике данных до регистрации заказа: строгие API-типы не поддерживают неизвестные поля. Список товаров работает с этой моделью напрямую; отдельной копии или этапа переноса нет. При окончательном сохранении `aiToPayload` после валидации распределяет товары по восьми обычным коллекциям API. Ручные изменения помечаются в `fieldSources`, обновления из чата сразу отражаются в списке. Отмена подтверждения создания не блокирует дальнейшие уточнения.

Проверка: открыть две двери разных размеров из чата, отредактировать цену одной при пустых остальных полях, скопировать/удалить товар, сохранить и перезагрузить страницу. Обе строки и ручные изменения должны восстановиться; неизвестная стоимость не отображается как ноль. Предоплата и скидка редактируются в общих полях заказа.
