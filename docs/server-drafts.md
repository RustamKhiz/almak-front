# D1: серверные черновики и переписки

Состояние на 3 ноября 2026: реализовано и проверено локально; публикация этой функции ещё не выполнена. R1 уже опубликован: `almak` — администратор, `manager1` и `manager2` — менеджеры. Пароли в репозитории не хранятся.

## Поведение

- Обычные и ИИ-черновики сохраняются на сервере. Допустим неполный документ, включая одно известное поле. Проверка полноты остаётся перед регистрацией заказа.
- Общая очередь доступна всем трём аккаунтам, «Мои» учитывает автора или импортирующего пользователя. Видны автор и последний редактор. Архив можно открыть и восстановить; заказ при архивации не изменяется.
- Один ИИ-чат связан с одним черновиком. История, неотправленный текст и результаты распознавания сохраняются на сервере. После регистрации сохраняется ссылка на заказ.
- Автосохранение через 350 мс. В чате обычный статус сохранения скрыт; ошибки и конфликты остаются видимыми. Пока сеть недоступна, введённое остаётся в памяти открытого приложения, показаны ошибка и повтор сохранения. Браузер предупреждает о несохранённом вводе. Windows-приложение перед закрытием и установкой обновления запрашивает сохранение у фронтенда и ждёт подтверждения сервера. При ошибке или отсутствии ответа за 15 секунд окно остаётся открытым. Принудительное завершение процесса и выключение питания этот механизм не обрабатывает.
- При первом открытии чат дожидается загрузки серверных записей и восстанавливает последнюю переписку с неотправленным текстом. Явный выбор нового чата имеет приоритет над поздней загрузкой. Поле ввода растёт до 160 пикселей (не более четверти высоты экрана), затем прокручивается внутри; Shift+Enter добавляет строку, Enter отправляет сообщение.
- При конфликте чужая версия не заменяет введённое. Можно скачать свой вариант, сохранить отдельный черновик или явно загрузить серверный. История остаётся у исходного чата; отдельная копия переносит документ. Для уже зарегистрированного заказа доступны скачивание и ссылка на заказ, создание дубликата через конфликт не предлагается.
- Обновление при открытии, возврате фокуса и каждые 15 секунд. Открытый редактор не заменяется фоновыми чужими правками, включая время заполнения окна товара. Смена аккаунта отменяет ожидающие запросы; несохранённый буфер скрывается и доступен только при повторном входе прежним пользователем в том же окне.

## API и согласованность

Все пути относительно `/api`, требуют авторизации и `drafts.write`; отправка ИИ также требует `assistant.use`.

| Метод | Путь                                    | Назначение                                                                     |
| ----- | --------------------------------------- | ------------------------------------------------------------------------------ |
| GET   | `/order-drafts?limit=100&offset=0`      | Страница общих записей, включая завершённые чаты; `mine=true`, `archived=true` |
| GET   | `/order-drafts/:id`                     | Полный документ, метаданные и история                                          |
| POST  | `/order-drafts`                         | Создание с клиентским UUID и request ID                                        |
| PUT   | `/order-drafts/:id`                     | Изменение по `baseRevision` и request ID                                       |
| POST  | `/order-drafts/:id/messages`            | Текст, request ID и ожидаемая ревизия; контекст читает сервер                  |
| POST  | `/order-drafts/:id/undo`                | Отмена последнего применения ИИ с контролем ревизии                            |
| POST  | `/order-drafts/:id/archive`, `/restore` | Архив и восстановление                                                         |
| POST  | `/order-drafts/import`                  | Повторяемый импорт одной прежней записи                                        |

В БД добавлены `order_drafts`, `draft_messages`, `draft_ai_requests`, `draft_mutations`. Документ имеет `schemaVersion=1`, `kind=ai/manual`, состояние `active/converted/archived`, ревизию, авторов и связь с заказом. Документ хранит частичные поля, источники, снимок отмены и прежний полный `editorState.payload` без потери ручных исправлений.

Проверка ревизии и запись атомарны. При конфликте API возвращает `409` с актуальной записью. Повтор неподтверждённого сохранения отправляет прежний request ID и прежний снимок до отправки последующих правок. Повтор старой операции после другого изменения не считается новым сохранением.

Пользовательское сообщение записывается до вызова DeepSeek. Транзакция не удерживается во время внешнего запроса. Поздний ответ не затирает ручные изменения. Повтор незавершённого сообщения после перезагрузки повторно использует серверную операцию; повтор завершённого request ID не создаёт дубликат.

`POST /orders` дополнен `draftId` и `draftRevision`: создание заказа, начального платежа и переход в `converted` выполняются одной транзакцией. Повтор возвращает уже созданный заказ. Во время активной обработки ИИ регистрация временно отклоняется с `AI_BUSY`.

## Перенос и ограничения MVP

Импорт запускает менеджер со страницы «Черновики». Читаются `order_drafts` и `ai_order_drafts_v1`; оригиналы не удаляются и не перезаписываются. UUID ИИ сохраняется; числовой ID обычного черновика получает устойчивое соответствие в пределах профиля импорта. Импорт фиксирует `imported_by`; неизвестные исторические авторы остаются неизвестными. Более свежая серверная запись не заменяется старым импортом. Ошибочные записи можно повторить после исправления, успешные не дублируются.

Полного offline-режима нет: основной источник — сервер, неподтверждённый буфер существует только в памяти окна. Потеря процесса до подтверждения сохранения может потерять этот буфер. LocalStorage используется для чтения прежних записей, идентификатора профиля импорта и настроек размера чата; новые черновики туда не записываются.

Список загружается по 100 записей с кнопкой «Загрузить ещё»; поиск и фильтр «Мои» в интерфейсе работают по загруженным записям. История пока возвращается целиком в конверте записи, до 500 сообщений и до 20 пользовательских уточнений; полноценную пагинацию сообщений и серверный поиск следует добавить при росте объёма. Размер документа ограничен 2 МиБ, до 100 товарных позиций. Хранение без автоматического удаления; сроки очистки ещё требуют решения.

ИИ для редактирования зарегистрированного заказа — отдельный этап A1. Повтор заказа — O1. Они в этот выпуск не входят.

## Проверки и выпуск

Локально выполнены Go-тесты и проверки на отдельном PostgreSQL: доступ менеджеров, авторство, конфликты, повторные запросы, импорт обоих форматов, архив, откат ошибки оплаты и параллельная регистрация без дубликатов. Angular проверяет сохранение, конфликты, смену аккаунта, перенос, собственную регистрацию и защиту перед обновлением. Через браузер пройден путь чат → товары → заказ с оплатой, обычный неполный черновик → архив → восстановление → перезагрузка, история в новом окне. Для сквозного теста ИИ использован локальный имитатор провайдера, рабочие данные не использовались. Резервная копия отдельной тестовой базы восстановлена в новую базу; проверены черновики, сообщения, заказы и платежи.

Перед публикацией: резервная копия PostgreSQL, затем backend с миграциями, проверка новых таблиц и API, web-фронт и отдельный выпуск Electron. Общий `pg_dump` должен включать новые таблицы; после выкладки проверить восстановление резервной копии и работу под каждым аккаунтом. Старые клиенты следует обновить: прежний локальный режим сам по себе не синхронизируется. Не удалять локальные оригиналы при выпуске или откате.
